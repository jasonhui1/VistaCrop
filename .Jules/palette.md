## 2026-05-15 - Explicit Focus Indicators for Icon Buttons
**Learning:** The project's custom CSS reset in `index.css` strips the default focus outlines from `<button>` elements, making interactive icon-only elements effectively invisible to keyboard users when focused. Standard tab navigation without these visual indicators breaks the keyboard navigation experience. Furthermore, tightly packed UI elements in flex layouts can cause focus rings to be clipped.
**Action:** Always verify keyboard accessibility on custom interactive elements. When building or modifying icon-only buttons, restore explicit focus states using Tailwind's `focus-visible` utilities (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[var(--accent-primary)]`) inline. Additionally, apply `focus-visible:z-10` or a similar stacking context adjustment to ensure the newly added focus ring is not clipped by adjacent flex or grid items. Always verify focus states programmatically with Playwright during testing if standard Tab navigation behaves inconsistently.
